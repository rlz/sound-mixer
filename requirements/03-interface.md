# 03. Interface

## Language

- English is the default interface language, including window text, error messages, and system permission descriptions.
- The HTML document declares English; the macOS app's development language is English.

## Icons

- Use free Font Awesome SVG icons in the React interface through the official `@fortawesome/react-fontawesome` component. Import only used icons from `@fortawesome/free-*-svg-icons` packages so they are included in the local build and work offline.
- Prefer icon buttons for familiar actions when the icon is clear, to conserve space. Give every icon-only button an accessible English name and a visible tooltip or equivalent text on focus/hover when the action may not be obvious. Decorative icons are hidden from VoiceOver. Device unavailability and errors are not conveyed with an icon alone.

## Window

- Keep the React interface split into focused modules: shared state types, native bridge, Zustand store, application composition, and reusable UI components. Components read shared state through Zustand selectors and send native changes through the typed bridge; they do not access Core Audio.

- The WebKit bridge accepts a versioned state snapshot from Swift and an allowlist of typed commands. The page sends a `ready` command after subscribing so the initial snapshot cannot be lost during startup. Every command includes a request ID and receives an accepted or rejected result. Swift validates required fields and ranges before saving; rejected commands leave saved state unchanged. Application gain commands accept only finite linear values from 0 through 10^(30/20); virtual Mix gain and Device volume commands accept only finite scalars from 0 through 1. Device volume and mute commands change Core Audio state without writing the mixer configuration and return a clear error when the device is unavailable or lacks the respective writable control. State snapshots combine discovered outputs with configured output mixes, buses, and BlackHole routes. Audio graph application is added with the audio engine.
- The initial device screen is read-only. It lists only discovered devices with output channels and saved output mixes, and shows each item's name, UID, output channel count, and availability. A saved UID with no matching output remains visible as disconnected. Input-only devices are not listed as outputs.

- The main window uses the full available WebView area. A persistent toolbar sits above three edge-aligned work areas; each area scrolls independently when its content exceeds the window height. Keep names, availability, levels, and primary actions visible without requiring repeated navigation. Physical input and output availability appears as a colored dot immediately before the device name, without a visible status label; give the dot an accessible status name and hover tooltip. Keep capture progress and specific unavailability reasons in text. At the minimum supported window width, all three areas remain accessible.
- Prefer a dense layout with modest spacing and no redundant labels. Keep essential names, availability, values, and error explanations readable; use concise text and icon buttons for familiar actions to conserve space. Maintain keyboard and VoiceOver accessibility.
- Present input devices, output destinations, and mixes as consistent compact panels, not plain text lists. Input and output panels show live signal-level meters. Mix settings show live levels for the destination and its sources alongside their level controls. Each panel shows the item's name and state, plus icon-based management actions with accessible names. Keep state and error explanations understandable without relying on icons or color alone.
- Render meter values as peak amplitude from 0–1 full scale with a compact bar and a readable dBFS value. For visual position, allocate half the bar to −60…−12 dBFS and half to −12…0 dBFS so typical music peaks have room to move; 0 dBFS remains the right edge. Readings at or below −60 dBFS are shown as “No signal” with an empty bar, while unavailable or stale readings are “Inactive.” Keep the value on one line in a fixed-width, non-shrinking label so live readings do not reflow the panel. Keep the meter usable at larger system text sizes and expose its current value and inactive state to VoiceOver. Refresh from native runtime snapshots at up to 15 Hz; meter values are transient and are not saved.
- A muted source keeps its pre-mute input meter live. Its mix-source row shows “Muted” so the low post-mute reading is explained in the selected destination.
- A selected destination's mix meter measures only Sound Mixer's rendered digital signal. The left physical-output card measures process audio sent to that particular device, including audio outside its Sound Mixer mix, and shows zero when the device reports mute or zero main volume. It must not mirror an application playing only through another device. A virtual bus card uses its mix meter because it has no separate device signal. A BlackHole route card measures the assigned loopback input pair, including audio sent to that pair by other applications; its selected mix meter remains Sound Mixer's rendered contribution. A running tap with no recent audio buffers is an idle/no-signal state, not a capture error; show capture errors only for actual permission or startup failures.
- A master “Mixing On/Off” switch with clear text state appears at the top, independently of the selected item.
- The header contains the Sound Mixer name and master “Mixing On/Off” switch with a clear text state, independently of the selected item.
- The wider left area lists output destinations in “Output Devices,” “Virtual Buses,” and “BlackHole Routes” groups. All physical outputs appear whether or not a mix is configured, except the BlackHole driver device itself. “BlackHole Routes” contains only virtual routes created by the user; it does not list the underlying driver device as an output. Each physical output uses a compact card with its name, availability, live device signal meter, Core Audio device volume slider and value, and a separate mute button when the device exposes a writable mute control. Muting preserves the volume setting; unsupported controls are disabled with an accessible name and hover explanation; the card omits redundant Disconnected, Muted, and unavailable-control captions. Virtual bus and BlackHole route cards also show their live destination signal meter and saved Mix gain slider with a percentage value. Cards select an item, and selection is distinguishable without relying on color alone.
- When the interface first receives its state and no destination is selected, select the first available physical output; if none is available, select the first virtual bus or BlackHole route. This gives mix-source actions a clear destination while preserving any selection the user makes.
- The center area shows the selected destination's settings and mix: name and type, availability, channel count, UID or route details as appropriate, route error, a live output signal-level meter for physical outputs, source rows with per-source live signal-level meters and level controls, and add-source action. Show a BlackHole route's device name in the mix heading using the current device snapshot, falling back to its UID when no name is known; keep the UID in route details. When a BlackHole route is a mix source, resolve its name and state from the same current route snapshot used elsewhere in the interface, falling back to its UUID only if the route is missing. Left-card Mix gain sliders apply changes during pointer or keyboard movement; intermediate updates are coalesced while a bridge command is in flight. On destination change, every slider immediately shows that destination's confirmed value and does not carry a prior destination's interaction state. Virtual item names are editable here; physical device names are read-only. Keep source rows compact and scannable.
- The right area lists every discovered physical input device, saved input devices that are currently disconnected, configured BlackHole stereo-pair inputs, internal virtual buses, and application sources already used in a mix. Show each bus here as an internal virtual input with its bus name, live bus-output meter, and an Add to mix button, using the same UUID-backed source as other mix controls. Do not add global mute or physical channel-routing controls to buses. Disable Add to mix if the bus is already in the selected mix or is the selected bus destination. Under “BlackHole Inputs,” show one stereo input row for every route created in the left “BlackHole Routes” output group, using that route's name and automatically assigned channel pair (for example, “BlackHole 3/4”). BlackHole routes are stereo only. This is the same route identity and assigned output pair; do not create a second input route or ask the user to select its channels. Show the pair as unavailable if the device is disconnected or either channel is unavailable on its input side. Input devices and BlackHole pair inputs show availability, capture state, and live signal-level meters. Added applications show availability and capture state. A previously added application that is not running remains in the list as unavailable and resumes automatically when a matching process is available again. Do not populate this area with every running application by default: provide an add-application action that opens a separate searchable catalog of eligible applications. Each source row has an Add to mix button. It is disabled when that source is already in the selected mix, and its enabled state updates whenever the selected destination changes based on that destination's mix. Remove sources from the mix in the selected destination's mix settings, not from the source panel.
- Each physical input device, BlackHole pair input, and added application has a mute control in the right area. Muting a source prevents it from contributing to every route, without deleting its mix rows or changing their per-route levels. Mute state is saved and restored. Unmuting makes the source eligible to contribute again when it is available and permitted.
- Selecting an output opens its settings in the center area. Selecting a virtual bus or BlackHole route opens its settings there; its saved name is edited there and persisted after native confirmation. Muting does not stop capture, so an actively captured muted source can continue to show its input level.
- Application mix rows show App gain in dB from mute at the left endpoint through 0 dB (unity) to +30 dB in 0.5 dB steps. Show the confirmed dB value, including a plus sign above unity. This gain affects only that application row in the selected mix; Inputs stays pre-gain, while row and destination meters reflect the boosted signal. The engine limits the final output to full scale, so sustained boost into the limiter can distort.
- Physical output cards show Device volume from 0% to 100% using the live Core Audio main-volume scalar. The controls work even before a mix is configured and while mixing is off, reflect changes made outside Sound Mixer, and show the current device value after native confirmation. When the output exposes a writable mute control, its separate button toggles mute without changing the current volume. Setting volume to 0% also enables mute; setting it above 0% disables mute. During pointer movement, send the first device-volume change immediately, then apply the latest value after each Core Audio write completes; keep the control responsive throughout. A disconnected output disables the controls; a device without a readable and writable main control shows a disabled volume control and a tooltip explanation, without falling back to digital Mix gain. Sound Mixer restores the previous device volume and mute state on normal exit when each still has its last app-set value. Physical mix output stays at unity.
- Virtual bus and BlackHole route cards in the left area show saved software Mix gain from 0% (silence) to 100% (unity). These controls do not change any Core Audio device volume. Device volume, virtual Mix gain, and application App gain have distinct labels and accessible names.
- Configured outputs, buses, and BlackHole routes show their source rows with per-source levels and removal controls. A physical input row has a compact “Channels” button that opens an inline channel editor in the selected mix. The panel lists every discovered input channel by number, shows its live level meter, and provides four routing choices per channel: Ignore, First, Second, and Both. Apply choices only to that row in that destination mix. New mono inputs default to Both; new stereo and multichannel inputs default to channel 1 → First, channel 2 → Second, and remaining channels → Ignore. Show a channel-gain control as well. Channel gains are linked by default and adjusted with one shared slider; turning linking off exposes an individual slider for each channel, initialized to the shared gain. Turning linking back on preserves the channel levels' relative differences. The shared slider scales all channel levels together while preserving those differences (normalizing the highest channel to the shared slider value); it does not copy channel 1's value to every channel. Clearly indicate the link state and that the shared slider controls all channels. The panel clearly shows confirmed saved routing and levels. Use accessible labels such as “Input channel 3 routing” and “Input channel 3 level,” and keep the panel keyboard-operable and compact. New rows can be added from available physical inputs, applications with active output, and buses through the Add to mix buttons in the source panel; remove existing rows here in the selected mix settings. Missing saved sources remain visible and removable. Destination device volume or virtual Mix gain remains separate from per-source controls.
- A saved but missing output stays in the Output Devices group after restart. Its configured mix remains saved and is shown inactive while that UID is disconnected; it automatically becomes active again when that same device returns. The user can select it, inspect and reset its mix settings. The macOS device itself is not removed. Device absence never deletes configured mix settings automatically.
- An add button creates an internal bus or BlackHole route. A virtual item's name can be edited inline or in its settings.
- BlackHole route creation requires an available discovered BlackHole output; users do not select or configure channels or enter a name. Native code allocates the lowest available adjacent stereo pair in order (1/2, 3/4, 5/6, and so on), bounded by the device's output channel count, and generates the name from that pair, such as `BlackHole 1/2` or `BlackHole 3/4`. The generated name remains until the user renames the route; the custom name is then saved and shared with the corresponding BlackHole input row. Native validation handles exhausted pairs and a base output mix on the same device, and explains when no pair is available. Existing routes show their UID and automatically allocated pair. If a route is used as an input source anywhere, deleting it first shows a confirmation that its source rows will also be removed from every mix. On confirmation, remove all references and the route in one atomic save; on cancellation or save failure, preserve the complete configuration.
- Bus creation and renaming use an in-interface form so name entry works consistently in WKWebView.
- Deleting a virtual bus that is still used as a source by another mix is rejected with a validation error; remove those source rows first. Bus names are trimmed, must be non-empty, and are limited to 64 characters.
- The center add-source picker and right-side Inputs panel expose the same internal buses as mix sources. Applications are added explicitly from the searchable application catalog opened from Inputs; the catalog lists eligible currently running applications not already configured, searches names and bundle identifiers, and does not add them merely by browsing. Existing configured applications remain in Inputs when their process is unavailable.
- When adding a source, unavailable items include a reason. The catalog does not offer a new row for a missing input device.
- An existing input stays in its mix row when its device is missing, including at launch. It is shown unavailable and can be explicitly removed from the mix. The interface does not offer to create a new row for a missing device, and device absence never removes a source row automatically.
- The channel-routing panel is available for physical input sources regardless of channel count. BlackHole stereo-pair inputs always carry their configured pair as left/right stereo. Application taps remain stereo mixdowns and virtual buses remain stereo; their existing source controls remain unchanged.

## States and feedback

- An empty mix explains how to add a source.
- A destination has editable mix settings without a separately created mix object. An output mix is saved only while it has settings; removing its last source makes it equivalent to no mix. Bus and BlackHole route mix values at their defaults with no sources are likewise treated as absent. The mix editor always remains available for the selected destination. Its top Reset button clears its sources and restores default gain; for a physical output this removes the saved output mix, while buses and routes remain and only their mix settings reset.
- Microphone or system-audio permission denial appears beside the affected source and provides an action to open System Settings.
- Source rows show capture progress, active capture, permission denial, or the native unavailable reason. A denied source provides a validated bridge action that opens the relevant macOS privacy settings pane.
- Missing BlackHole and lack of free channels are explained before route creation.
- A saved BlackHole route remains visible and removable when the driver or selected instance is missing. For missing devices, show the last-known name if saved and the UID in details; otherwise use the UID as the name. Status text explicitly says the device is disconnected.
- A route validation error identifies affected items and does not change the active audio graph.
- Level and name changes appear after successful confirmation from Swift. On failure, the UI restores the confirmed value and shows the reason.
- While mixing is off, sliders and mix contents remain visible and editable; the interface states that Sound Mixer is not currently outputting audio.
- Swift state snapshots combine saved items and discovered devices, reporting availability and each route's stop reason separately. After a missing device is connected or removed, the interface updates from a confirmed snapshot without restarting the window.

## Accessibility

- All actions are keyboard accessible; sliders have text labels and numeric values. Static interface text, including labels inside selection buttons, can be selected and copied with the standard macOS Copy and Select All commands.
- Level sliders keep their in-progress value stable while native state snapshots arrive. Commit the value on pointer release or keyboard adjustment, then reconcile the displayed value with the confirmed native state; rejected edits return to the last confirmed value. After interaction and any in-flight write finish, an external Core Audio volume change updates both the numeric value and slider thumb, even if a prior device readback differed slightly from the requested value.
- Respect the macOS system text size, contrast, and dark mode.
- Expose the physical-device availability dot as accessible text and a tooltip; keep capture state and device errors visible in text.
