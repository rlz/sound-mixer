# Development Plan

Statuses: `[ ]` = not started, `[~]` = in progress. Tasks are ordered by dependency; design decisions and acceptance details live in `requirements/`.

## 1. Domain model and configuration

- [~] Add per-mix physical-input routing and gain in configuration schema v4. **Done when:** each physical-input mix row stores routing and gain per hardware channel; routing defaults to mono → outputs 1/2, source 1 → output 1, source 2 → output 2, remaining source channels unassigned; gains default linked at unity; independent levels and link state serialize and validate per mix. Domain defaults, validation, initialization on add, typed bridge updates, and an accessible channel routing/gain editor are in place. Linked gains preserve channel ratios; per-channel meters and realtime application are implemented, with live multichannel verification pending.

## 2. Native audio pipeline

- [~] Apply audio graph edits incrementally without interrupting unrelated playback. **Done when:** adding/removing a virtual bus or mix input preserves every unaffected capture session, output unit, source converter, and ring; only endpoints in the changed dependency closure are updated; callback-visible snapshots remain valid for in-flight renders; device reconnect/format changes affect only dependent resources. One HAL output unit serves each physical device; nonempty virtual buses have independent meter pumps, empty bus changes are configuration-only, and input channel changes rebuild only dependent renderers; capture attempts and device meters follow source/device diffs. Unchanged fanout topology ignores subscriber order and skips publication. Build and graph-diff tests pass; hardware-change and playback-continuity checks still need manual verification on a Mac. Decision and acceptance details are in `requirements/02-routing-and-mixing.md`.

- [~] Finish physical output. **Done when:** physical outputs, receive mixes across their available channels. First-source addition creates the physical output mix atomically. Format conversion quality and device-level routing remain to verify.

Unused discovered inputs now start capture and feed meters; multichannel queues, per-channel meters, and per-mix routing/gain rendering are implemented; Scarlett signal and channel-isolation behavior still need manual verification on a Mac.
- [~] Handle device disconnection, reconnection, and format changes. **Done when:** the same UID resumes valid routes after compatibility checks, other routes continue independently, and mixing Off never starts capture or output. Same-device reconnect and changed-format checks remain.
- [~] Keep application-tap creation from restarting the graph or blocking the interface. **Done when:** adding an application during headphone playback keeps the window responsive and playback continuous, private tap aggregates never appear as input devices, and unrelated process-list changes do not restart audio. The internal aggregate is filtered, unrelated processes are ignored for routing, and Core Audio setup now runs on a serial control queue; live Mac regression remains.
- [~] Add global application input gain for quiet process taps. **Done when:** the Inputs card can boost the captured application through +30 dB with unity at 0 dB, while every mix row remains at unity maximum (0 dB); bridge and saved configuration validate both ranges, input/row/destination meters reflect their respective pre- and post-gain signals, and gain edits apply smoothly without restarting active audio. Global source gain is implemented; live tap and smooth-edit verification remain.
- [~] Finish master-switch and app-exit lifecycle checks. **Done when:** Off, exit, and relaunch release resources and resume only when the saved state and current devices allow it. The user confirmed exit and route restoration work. Resource release and master-switch state checks remain.
- [~] Finish startup restoration and unavailable-route reporting. **Done when:** saved Off stays off, saved On starts available routes, and unavailable routes remain editable with a specific reason. The user confirmed route restoration after relaunch. Saved Off behavior and unavailable-route feedback remain to verify.
