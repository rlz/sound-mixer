# Development Plan

Statuses: `[ ]` = not started, `[~]` = in progress, `[x]` = complete. Tasks are listed in dependency order. Each task has a verifiable result.

## 0. Research and scaffold

- [x] Define scenarios, terminology, architecture boundaries, and acceptance criteria in `README.md`, `AGENTS.md`, and `requirements/`.
- [x] Create the macOS 15+ Xcode app project, WebKit shell, and React/TypeScript/Tailwind project. **Done when:** a clean build opens a window with the local interface without network access.
- [x] Set up SwiftFormat, SwiftLint, Prettier, ESLint, and CI with four-space indentation. **Done when:** the same checks run locally and in CI, and tool versions are pinned.
- [x] Keep generated web build output out of Git and provide one command to build the interface and macOS app. **Done when:** `Web/dist` is ignored and `./scripts/build-all.sh` builds both from source.
- [x] Make English the default application language. **Done when:** current interface text, load errors, and permission prompts are in English; the HTML language and macOS development language are set to English.
- [x] Prototype Core Audio input and output discovery, microphone capture, output to two devices, and format changes. **Done when:** working APIs, measurements, limitations, and the sample-rate decision are documented in `prototypes/core-audio/README.md`. Client-format switching was verified; external hardware-format changes remain for integration testing.
- [x] Prototype process taps on a supported macOS version: process listing, permission, audio from one application, and prevention of self-capture. **Done when:** a runnable prototype and verified limitations are documented. The first permission prompt and denial remain for integration testing in a signed app.
- [x] Check audio behavior and tap cleanup when mixing is disabled and when the prototype exits normally or crashes. **Done when:** `prototypes/process-tap/lifecycle.sh` passes; a listener confirms uninterrupted system-output audio when capture stops and after `SIGKILL`. Limitations are documented.
- [x] Check BlackHole on a multichannel device and how to write to a selected channel pair. **Done when:** a reproducible prototype and conclusions about valid channel layouts are documented. BlackHole 64ch loopback confirmed mono channel 17 and stereo pairs 3–4 and 63–64 by reading all 64 channels.

## 1. Domain model and storage

- [x] Define models for devices, buses, routes, sources, and levels, stable identifiers, and the configuration schema. **Done when:** serialization tests cover the models.
- [x] Extend configuration to v2 with last-known-name metadata for configured UIDs. **Done when:** a device missing at startup can be labeled with its saved name; a UID without a name is shown as the UID. Older development schemas are rejected; migration is not required before release.
- [x] Implement graph validation for node existence, cycles, BlackHole channel conflicts, and format compatibility. **Done when:** tests reject invalid changes before application. Structural validation and per-endpoint runtime device checks are covered by tests.
- [x] Implement automatic atomic saving of every accepted change, including the master switch state, with schema version checks. **Done when:** configuration is restored after restart without manual saving; changes to last-known names and removal of the last reference to a UID are saved; a corrupt or unsupported file is handled without a crash. The native configuration store is wired into startup; future edit entry points must use its transaction API. Configuration migration is not required; invalid saved configuration is discarded and reset to empty defaults.

## 2. Native audio pipeline

- [x] Observe Core Audio inputs and outputs and their availability. **Done when:** the list updates without restarting, and settings are tied to UIDs. The native device catalog observes HAL list and relevant device-property changes and publishes UID-keyed snapshots; the interface bridge will consume these snapshots in the interface task.
- [x] Show a read-only list of discovered Core Audio outputs in the app. **Done when:** the native snapshot populates device names, UIDs, output channel counts, availability, and updates after device changes; no sample devices are shown. This is the visible checkpoint before returning to the remaining core work.
- [x] Match saved UIDs to discovered devices at launch and on every HAL change. **Done when:** a saved output, input, or BlackHole route remains unavailable if its device is missing at startup; absence does not corrupt configuration or block independent routes; the state snapshot distinguishes saved and discovered devices. The native snapshot now unions all configured UIDs with current Core Audio devices and reports their saved roles, live presence, availability, channel counts, and best-known name. Audio resumption remains part of the engine and reconnection tasks.
- [x] Implement the stereo mixing engine, source and master levels, smooth level changes, and clipping protection. **Done when:** audio tests verify levels, absence of clicks, and basic stability. Realtime-safe stereo summing with 10 ms gain ramps and a finite-safe hard limiter is implemented. XCTest coverage includes level preservation, gain transitions, overload, and repeated variable-sized blocks; equivalent runtime checks passed in a standalone harness because SwiftPM's cache is restricted. Xcode app build, formatting, and lint pass. Native device output and end-to-end route stability are covered by subsequent pipeline tasks.
- [x] Add mono routing to the left, right, or both channels. **Done when:** tests verify expected samples in both channels.
- [x] Implement internal virtual buses and safe replacement of the active graph. **Done when:** multiple mixes can use one bus and a cycle cannot start. Validated immutable snapshots now hold the shared bus graph in dependency-first render order, and the configuration store publishes one only after validation and atomic persistence succeed; invalid edits preserve the accepted snapshot. The native renderer still needs to consume these snapshots in the subsequent output-pipeline task.
- [~] Output to physical devices and BlackHole routes with channel selection. **Done when:** independent mixes play on selected outputs and overlapping channels are rejected. A routing coordinator now applies the saved graph to HAL outputs and source capture. It creates one bounded SPSC stereo queue per source and endpoint, converts Float32 capture to 48 kHz, renders shared buses in dependency order, applies mono placement, and writes to selected multichannel output channels. Device snapshots retain the runtime AudioDeviceID; queue drop and underrun counts are available from the coordinator for diagnostics. Physical output, format conversion quality, and overlapping-channel rejection still need device-level verification.
- [~] Handle device disconnection, reconnection, and format changes. **Done when:** the same UID resumes valid audio automatically while mixing is on, after format, channel, and permission checks; a different UID does not replace it, and the off switch does not start audio. HAL device snapshots trigger route reconstruction by UID, and output startup errors are now shown on the affected output. Same-device reconnect, changed formats, channel rejection, and Off behavior still require Mac integration verification.
- [~] Implement the master switch and release audio resources when switching off or exiting. **Done when:** all mixes stop and resume, and normal audio from other apps works after Sound Mixer exits. The saved switch state now controls routing startup; Off and app termination stop capture and output resources. Confirm resume behavior and normal system playback on a Mac.
- [~] Start from saved state after validating the graph, devices, and permissions. **Done when:** saved Off does not start the audio pipeline; saved On starts available routes and reports the others. Startup applies the validated saved graph after device and process discovery, and starts only currently available endpoints. User-visible reporting for unavailable routes and a saved On/Off device-level check remain.

## 3. Interface and integration

- [x] Split the React interface into focused modules and adopt a modern state store. **Done when:** shared state, bridge, application shell, and reusable controls are separated from the entry point, with Zustand handling UI and native snapshot state. The interface is split across typed state, bridge, store, app composition, and reusable header, master switch, and group components; Zustand is pinned in the web package manifest and lockfile.

- [~] Implement a typed Swift ↔ WebKit bridge, command validation, and state snapshots. **Done when:** an invalid command is rejected without changing the audio graph. Snapshots now include destination mix rows; add, remove, level, and mono-placement commands go through validated atomic configuration updates and trigger routing reconstruction. Native audio graph application is connected; invalid-command behavior still needs end-to-end verification.
- [x] Add Font Awesome Free to the React interface for local SVG bundling. **Done when:** package versions are pinned, an icon appears on the current screen, and the build needs no CDN.
- [~] Build the left panel with device, bus, and BlackHole groups, selection, and sliders. **Done when:** all outputs appear and sliders control the native mix. The selectable groups and physical output level sliders are in place; bus and BlackHole level editing awaits native edit commands.
- [x] Add the master switch and a textual disabled state to the window. **Done when:** the state is keyboard accessible, confirmed by Swift, and restored at launch. The switch uses the saved native state, sends validated changes through the bridge, and states clearly when Sound Mixer is not outputting audio.
- [~] Add creation, renaming, and deletion of virtual buses and BlackHole routes, with channel selection. **Done when:** these flows work with validation errors and state restoration. Virtual bus create/rename/delete commands and controls are implemented with persisted validation; BlackHole route creation/deletion now saves a selected UID and mono/stereo channel selection with native availability, range, and conflict validation. Existing routes show their channels and can be deleted. Integration on a Mac with BlackHole remains.
- [~] Build the right panel with the source catalog, mix rows, levels, and mono input placement. **Done when:** a user can assemble a mix without editing files. Selected destinations expose source addition from available inputs, active applications, and buses; rows show availability, level, removal, and input mono placement. Global source catalog, live meters, app eligibility search, and Mac capture verification remain.
- [~] Build the compact three-area interface: destination list on the left, selected destination settings and mix in the center, and physical inputs plus explicitly added applications on the right. Add global per-source mute, live input meters, and unavailable states for saved applications that are not running; persist mute state in configuration schema v3. **Done when:** all three areas stay scannable, a source mute affects every route and restores after restart, and an added application becomes unavailable when stopped and active again when relaunched. Schema v3 now persists global mute identities; the audio renderer silences them across routes and the application catalog exposes a mute control. Input mute controls, the compact three-area layout, live meters, and end-to-end restart verification remain.
- [~] Allow removal of a saved mix for a missing output and removal of a missing input from a mix. **Done when:** these actions work after startup without the devices; deletion updates and saves configuration without affecting Core Audio; an unconfigured available output remains listed. Missing-device mixes and source rows remain saved and inactive/unavailable; explicit mix removal is now available and only edits Sound Mixer configuration. Missing source rows already have an explicit Remove action. Persistence after reconnect still needs Mac integration verification.
- [~] Show permission states, missing devices, missing BlackHole, and route errors. **Done when:** saved items remain visible after startup without their devices, show a name or UID and an unavailability reason, and can be removed; reconnection updates state without reopening the window. The UI now shows disconnected output reasons and source capture/permission states, and exposes a System Settings action for denied capture; the Mac permission and missing-BlackHole paths still need end-to-end verification.
- [~] Finish capture of input devices and application sources with permission handling. **Done when:** selected sources produce separate streams, denial appears on the affected source, and independent sources keep running. Discovery and the `AudioCaptureCoordinator` backend are already implemented: it owns HAL input and process-tap sessions, streams buffers with per-source state, and releases resources on shutdown. Finish this after the audio engine, native bridge, source-mixing interface, and permission-state UI are ready; add source start/stop commands, deterministic TCC denial mapping, and signed-app verification.
- [ ] Check keyboard use, VoiceOver, contrast, dark mode, and larger text. **Done when:** primary flows work without a mouse.
