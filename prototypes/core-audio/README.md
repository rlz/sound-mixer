# Проверка Core Audio HAL

Прототип запускается отдельно от приложения и не меняет системный выход или номинальную частоту устройства. Он перечисляет устройства с UID и числом каналов, захватывает один вход, считает уровень сигнала и одновременно выводит тихий тестовый тон 440 Гц на два разных стереовыхода. По флагу он останавливает оба выхода, меняет их клиентский формат и запускает снова.

```bash
bash prototypes/core-audio/run.sh
bash prototypes/core-audio/run.sh probe --input BuiltInMicrophoneDevice \
    --outputs BuiltInSpeakerDevice BlackHole2ch_UID --seconds 5 \
    --switch-client-rate 44100
```

UID в примере относятся только к проверенному Mac. На другом Mac нужно сначала запустить команду без аргументов и подставить найденные UID. Для захвата входа разрешите микрофон процессу, запускающему прототип. Выходной сигнал имеет амплитуду 0,05; перед запуском проверьте громкость динамиков. Бинарный файл собирается в `.build/`.

Форматирование и линтер: `.tools/bin/swiftformat prototypes/core-audio/main.swift --lint --config prototypes/core-audio/.swiftformat --cache ignore` и `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer .tools/bin/swiftlint lint --strict --no-cache --config .swiftlint.yml prototypes/core-audio/main.swift`.

## Проверено 23 сентября 2026 года

Среда: macOS 27.0, Xcode 27.0, MacBook Air; Swift CLI при запуске с доступом к аудиоустройствам. Без доступа к аудиоустройствам окружение возвращало пустой список, поэтому результаты ниже получены при разрешённом доступе.

- `kAudioHardwarePropertyDevices` и `AudioObjectGetPropertyData` вернули устройства и их UID. `kAudioDevicePropertyStreamConfiguration` разделил входные и выходные каналы: встроенный микрофон — 1 вход / 0 выходов, встроенные динамики — 0 / 2, BlackHole 2ch — 2 / 2. Микрофон имел номинальные 44,1 кГц, оба выбранных выхода — 48 кГц. У обнаруженного Multi-Output Device были 0 / 0 каналов и 0 Гц; его нельзя считать доступным выходом только по имени.
- `kAudioUnitSubType_HALOutput`, `kAudioOutputUnitProperty_EnableIO`, `kAudioOutputUnitProperty_CurrentDevice`, `kAudioOutputUnitProperty_SetInputCallback` и `AudioUnitRender` работали для встроенного микрофона: за 5 секунд получено 227 328 кадров, пиковый уровень 0,065. Показания уровня зависят от звука рядом с микрофоном.
- Два отдельных HAL Output AudioUnit с `kAudioUnitProperty_SetRenderCallback` одновременно обработали 238 119 кадров на встроенных динамиках и 237 220 кадров на BlackHole. Проверены вызовы и обработка кадров; акустическое прослушивание и чтение сигнала с выхода BlackHole не проводились.
- Клиентский `kAudioUnitProperty_StreamFormat` обоих выходов удалось переключить с 48 на 44,1 кГц через остановку, `AudioUnitUninitialize`, установку формата, `AudioUnitInitialize` и повторный запуск. `AudioUnitGetProperty` подтвердил 44,1 кГц. Номинальные частоты устройств остались 48 кГц. Это проверка смены *клиентского* формата; внешнее изменение аппаратного формата во время работы не проверено.

## Решение для основного аудиотракта

Внутренний стереомикс работает на 48 кГц, Float32. Каждый вход приводится к этому формату до суммирования; каждый выход преобразуется в формат своего устройства. Клиентский формат AudioUnit не принимается за аппаратный: отдельно считываем `kAudioDevicePropertyNominalSampleRate` и фактически установленный `kAudioUnitProperty_StreamFormat`. Для независимых устройств нужны отдельные выходные callback и буферы; частоты их часов могут расходиться даже при одинаковых номинальных 48 кГц. Поэтому связь между миксом и выходом потребует буфера с контролем заполнения и компенсацией дрейфа при ресемплинге. Конкретные задержку, размер буфера и алгоритм компенсации выберем после измерений в задаче аудиодвижка.

Прототип не направляет микрофон на выходы: он независимо проверяет вход и два выхода тестовым тоном. Он не проверяет слышимость, динамическую смену аппаратного формата, переподключение устройства, разрешение после отказа и долговременный дрейф. Эти случаи остаются в задачах интеграции и приёмочной матрице. При смене аппаратного формата рабочий тракт должен остановить затронутый AudioUnit, заново прочитать свойства устройства, пересоздать преобразование и запустить маршрут либо показать ошибку; этот переход требует отдельной проверки.
